# Review Loops

Циклы ревью нужны для управления системой без переписывания истории.

## Daily Loop

Цель: не потерять день и не смешать факты с оценками.

1. Прочитать `CONTROL_PANEL.md`.
2. Проверить `planner.md`.
3. Проверить активные `quests.md`.
4. В конце дня добавить только новые факты в выбранный журнал, если есть
   прямой запрос пользователя.
5. Обновлять `stats.md` только если есть явный источник.

## Weekly Loop

Цель: синхронизировать планы и состояние.

1. Сверить `logbook.md`, `diary.md`, `battle-log.md`.
2. Проверить активные цели в `goals.md`.
3. Проверить ежедневные привычки в `habit-tracker.md`.
4. Зафиксировать найденные расхождения отдельно.
5. Не исправлять старые записи без подтверждения.

## Monthly Loop

Цель: сохранить большую картину.

1. Посмотреть `records.md`, `training-log.md`, `skill-log.md`.
2. Сравнить прогресс с `goals.md`.
3. Проверить домены `MONEY/`, `study-hub/`, `relationships/`.
4. Отдельно отметить системные долги.
5. Не сжимать месяц в один вывод, если потеряются детали.

## Sync Loop

Если найдено противоречие:

1. Назвать файлы.
2. Назвать тип расхождения.
3. Не выбирать "правильную" версию без источника.
4. Предложить запись в `sync-audit.md`.
5. Ждать подтверждение перед изменением существующего файла.

## Agent Quality Loop

После крупной задачи агент проверяет:

- не изменены ли источники без разрешения;
- не создан ли новый факт без основания;
- не смешаны ли факт и интерпретация;
- есть ли read-only проверка результата;
- можно ли продолжить работу без потери контекста.
