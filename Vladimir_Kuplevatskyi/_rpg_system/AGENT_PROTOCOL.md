# Agent Protocol

Протокол нужен, чтобы агент работал с RPG-папкой как с системой, а не как с
одним большим markdown-документом.

## Перед выполнением

1. Определи намерение пользователя:
   - записать новое событие;
   - найти информацию;
   - обновить состояние;
   - спланировать;
   - провести ревью;
   - изменить правила.
2. Найди слой из `RPG_ENGINE.md`.
3. Прочитай только нужные источники.
4. Проверь `INVARIANTS.md`.
5. Если задача может затронуть старые записи, остановись.

## Выбор файла

```text
событие дня -> diary.md или logbook.md
тренировка -> training-log.md
рекорд -> records.md
провал/битва -> battle-log.md
привычка -> habit-tracker.md
цель -> goals.md
план -> planner.md
задача -> quests.md
навык -> skills.md или skill-log.md
состояние персонажа -> stats.md
предмет/ресурс -> inventory.md
расхождение -> sync-audit.md
паттерн ошибки -> pattern-register.md
риск -> risk-gates.md
мысль -> reflections/
деньги -> MONEY/
учёба -> study-hub/
социальное -> relationships/
НОВА -> nova/
```

## Запись новой информации

Если пользователь явно просит "запомни", "запиши", "добавь в память":

1. Не отвечай, что запомнил, пока запись реально не сделана.
2. Выбери минимальный целевой файл.
3. Добавь новую запись append-only.
4. Не меняй старые формулировки.
5. После записи проверь файл чтением или audit-скриптом.

## Ревью системы

При ревью не исправляй старые записи. Разрешённый результат ревью:

- список расхождений;
- предложение нового индекса;
- новый read-only инструмент;
- новый шаблон для будущих записей;
- отдельный файл с планом миграции.

Запрещённый результат ревью:

- переписанный дневник;
- "улучшенные" старые формулировки;
- сжатие записей с потерей деталей;
- перенос памяти без подтверждения.

## Работа с риском

Если действие связано со здоровьем, деньгами, законом, отношениями или
публичной репутацией, сначала читается `risk-gates.md`.

Агент не должен выдавать рискованную инструкцию как игровую награду. RPG-слой
может мотивировать, но не отменяет реальные ограничения.

## Минимальный ответ после операции

```text
Сделано:
- что добавлено или проверено
- какие файлы затронуты
- какие источники не изменялись

Проверка:
- команда или наблюдение
```
