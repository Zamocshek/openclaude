# RPG Engine Architecture

Это архитектура управления уже существующей системой. Она не меняет правила
игры и не заменяет текущие режимы.

## Слои

### 1. Evidence Layer

Слой фактов. Его нельзя переписывать при оптимизации.

- `diary.md`
- `battle-log.md`
- `records.md`
- `training-log.md`
- `logbook.md`
- `skill-log.md`
- `worldview.md`
- `nova/*`

Роль: хранить сырой ход проекта, события, выводы, рекорды и память.

### 2. State Layer

Слой текущего состояния.

- `stats.md`
- `inventory.md`
- `quests.md`
- `goals.md`
- `planner.md`
- `habit-tracker.md`

Роль: показывать актуальную карту игры. Этот слой может обновляться только на
основании Evidence Layer или прямой команды пользователя.

### 3. Rules Layer

Слой правил симуляции.

- `game-loop.md`
- `reward-table.md`
- `skills.md`
- `achievements.md`
- `risk-gates.md`
- `map.md`

Роль: задавать механику, награды, ограничения, зоны и правила прогресса.

### 4. Operations Layer

Слой управления.

- `README.md`
- `SYSTEM_INDEX.md`
- `AGENT_OPERATIONS.md`
- `CONTROL_PANEL.md`
- `checklists/*`
- `_rpg_system/*`

Роль: помогать агенту выбирать правильный файл, порядок действий и безопасную
процедуру.

### 5. Domain Layer

Слой отдельных жизненных направлений.

- `study-hub/*`
- `MONEY/*`
- `relationships/*`
- `reflections/*`

Роль: хранить предметные разделы без смешивания с центральным дневником.

## Поток данных

```text
новое событие
  -> Evidence Layer
  -> State Layer, если нужно обновить состояние
  -> Rules Layer, если нужно применить награды/риски
  -> Operations Layer, если нужно запланировать следующий шаг
```

Обратный поток запрещён: производная таблица не может переписать источник.

## Типы объектов

- Event — событие, произошедшее в реальности.
- Quest — задача или сюжетная линия.
- Habit — повторяемое действие.
- Skill — прокачиваемая способность.
- Record — рекорд или цель рекорда.
- Risk Gate — обязательная проверка перед опасным действием.
- Sync Issue — расхождение между файлами.

## Definition of Done для RPG-задачи

Задача считается завершённой, когда:

1. Определён тип объекта.
2. Найден источник истины.
3. Изменён только разрешённый слой.
4. Старые записи не переписаны.
5. Если состояние обновлено, указан источник.
6. Если есть риск, применён `risk-gates.md`.
7. Результат можно проверить read-only аудитом.
