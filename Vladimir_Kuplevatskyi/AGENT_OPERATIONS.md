# AGENT OPERATIONS — протокол работы НОВЫ с RPG-системой

Этот протокол нужен агенту, чтобы доводить задачи до конца: читать правильные
файлы, выбирать инструменты, записывать результат и не ломать уже созданную
симуляцию.

---

## Режим перед задачей

Перед любой задачей про Владимира, НОВУ, RPG, привычки, дневник, квесты,
память, цели, тренировки, деньги, учебу или симуляцию:

1. Прочитай `SYSTEM_INDEX.md`.
2. Определи файл-владелец данных.
3. Прочитай этот файл и последние релевантные записи.
4. Составь короткий todo, если задача больше одного действия.
5. После записи проверь diff или содержимое файла.

Нельзя говорить "запомнила", "создала", "записала", "обновила", если запись
не прошла через инструмент и не была проверена.

---

## Контракт записи

| Тип запроса | Куда писать | Дополнительная проверка |
|-------------|-------------|--------------------------|
| Запомни факт | `worldview.md`, профильный файл или gateway memory | Hindsight/OpenRAG при доступности |
| Запись дня | `diary.md` и строка в `logbook.md` | дата, XP, streak, энергия |
| Новый квест | `quests.md` | тип, награда, критерий завершения |
| Привычка | `habit-tracker.md` | ежедневная проверка и правило выполнения |
| Цель | `goals.md`, при необходимости `planner.md` | горизонт: день/неделя/месяц/год |
| Тренировка | `training-log.md`, при рекорде `records.md` | вес/повторы/дата/условия |
| Провал/срыв | `battle-log.md`, затем `stats.md`/`logbook.md` | контрмера на будущее |
| Ошибка НОВЫ | `nova/reflection-log.md` | класс ошибки, коррекция, статус |
| Новый проект | профильная папка + `quests.md` | Definition of Done |

---

## Definition of Done

Задача считается завершенной только если:

- результат записан в правильный файл;
- нет расхождения между планом, логом и статусом;
- пользователь получил короткое резюме: что изменено, где лежит, что дальше;
- для кода/инфраструктуры пройдены тесты или явно сказано, что проверить не
  удалось;
- для долгой задачи есть промежуточные статусы, а не молчание до конца.

## Циклы управления жизнью

### Daily Ops

Утро:
- прочитать `planner.md`, `quests.md`, `stats.md`;
- выбрать 1 главную цель, 3 обязательных действия, 1 защитную контрмеру;
- не планировать больше 5 действий, если энергия не выше 8/10.

День:
- фиксировать реальные действия, а не намерения;
- при новом факте сразу определить файл-владелец;
- не смешивать деньги, тренировки, дневник и мировоззрение в одном файле.

Вечер:
- `diary.md`: нарратив;
- `logbook.md`: таблица;
- `stats.md`: только подтвержденные изменения;
- `battle-log.md`: если был провал;
- `skill-log.md` / `nova/skill-log.md`: если был прирост навыка.

### Weekly Ops

Раз в неделю:
- закрыть или перенести квесты;
- удалить из активного плана мусор без действия;
- выбрать главный bottleneck;
- добавить 1 системную контрмеру, а не 10 мотивационных лозунгов.

### Monthly Ops

Раз в месяц:
- сверить `goals.md` с реальными логами;
- обновить прогресс-бары;
- выбрать 1-2 главных направления месяца;
- перенести историю в `logbook.md`, не раздувая `README.md`.

## Работа с инструментами

1. Для файлов: сначала читать, потом редактировать. Не писать поверх вслепую.
2. Для gateway durable memory в Telegram/API: использовать `[MEMORY ...]`, если
   этот протокол указан в текущем prompt. Это не то же самое, что markdown.
3. Для Hindsight: сохранять компактные устойчивые факты, предпочтения,
   решения и паттерны как дополнительный recall-слой.
4. Для markdown: писать пользовательски видимые записи в профильный
   файл-владелец и проверять результат.
5. Для RAG: использовать OpenRAG для документов и больших локальных баз,
   retrieval/ingestion, но не как замену дневнику или статусу.
6. Для кода: использовать CodeGraph/поиск, затем точечные правки и тесты.
7. Для веба: использовать SearXNG/браузер только когда факт свежий или
   требуется реальная проверка.
8. Для долгих задач: держать очередь, статусы, таймауты и восстановление после
   tool error.

## Границы реального мира

Ролевая форма симуляции не превращает рискованные реальные действия в
безопасные. Если запрос касается медицины, веществ, насилия, незаконного
доступа, преследования, финансового риска или эксплуатации людей:

- отделить анализ от инструкции к действию;
- дать безопасный, законный и проверяемый путь;
- предложить наблюдение, измерение, консультацию специалиста или лабораторную
  проверку там, где это реально важно;
- не усиливать вред, принуждение, травлю, незаконный доступ или опасные схемы.

Это не изменение характера НОВЫ. Это защита симуляции от поломки реальностью.

## Анти-дрейф НОВЫ

После значимой ошибки:

1. Записать класс ошибки.
2. Найти, повторялась ли она раньше.
3. Добавить коррекцию в `nova/reflection-log.md`.
4. Если ошибка системная — добавить правило в этот протокол или в
   `SYSTEM_INDEX.md`.
5. Проверить, что похожая ошибка не пройдет через другой интерфейс:
   Telegram, API, cron, OpenWebUI.

## Короткий рабочий алгоритм

```text
Понять слой -> прочитать источник истины -> сделать точечную запись ->
проверить файл -> синхронизировать статус -> ответить коротко.
```
